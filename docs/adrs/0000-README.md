# Architecture Decision Records

1. [Web framework: FastAPI (v1) vs. Django for the rebuild](0001-fastapi-vs-django.md) — rebuild on Django + DRF instead of keeping v1's FastAPI app, since Django's built-in auth, ORM, admin, and storage give durable multi-tenant job state essentially for free. Amended by [ADR 0016](0016-knox-multi-token-auth.md): its DRF `TokenAuthentication` was replaced by django-knox.
2. [Task execution framework for the remediation pipeline](0002-task-execution-framework.md) — use Django's first-party `django.tasks` (`ImmediateBackend` locally, swappable to Cloud Tasks later via config) to run remediation out-of-band, avoiding Celery/RQ's always-on broker and worker requirement.
3. [Remediation pipeline: artifact-based step architecture](0003-pipeline-steps-and-branching.md) — the pipeline is a fixed sequence of six responsibility-based stages, each recording its outcome as an immutable `RemediationArtifact` row. One renamed step (`finalize_tags` → `finalize_metadata`) — see [ADR 0010](0010-fix-opendataloader-hybrid-tagging-upstream.md). Amended by [ADR 0013](0013-pipeline-continues-past-a-failed-step.md): a failed step no longer fails the whole job — the pipeline now runs to completion regardless, since a partially-remediated document is more useful than none.
4. [OCR/tagging engine: OpenDataLoader as a pinned dependency](0004-ocr-tagging-engine.md) — pin Java + OpenDataLoader (hybrid Docling mode) as a real, named dependency for the `ocr`/`finalize_metadata` stage rather than hiding it behind a generic swappable OCR interface, since OpenDataLoader can't cleanly separate OCR from tagging anyway. Amended by [ADR 0010](0010-fix-opendataloader-hybrid-tagging-upstream.md): OpenDataLoader's hybrid+tagged-pdf combination was found broken, then fixed directly via a fork contributed upstream, rather than worked around downstream.
5. [Alt-text engine: Claude Vision](0005-alt-text-engine.md) — use Claude Vision for the `alt_text` stage for now, since v1 already validated it end-to-end, while flagging OpenDataLoader's built-in SmolVLM output as untested against the WCAG bar and worth a real future comparison. Amended by [ADR 0011](0011-close-alt-text-engine-comparison.md): that comparison was decided against, not run.
6. [General mechanism for tracking engine/service comparisons](0006-engine-comparison-tracking.md) — add a permanent, reusable `EngineComparisonSample` table (gated by `RUN_ENGINE_COMPARISON_LOGGING`) for logging and manually comparing any two services' output on the same input, first used to compare SmolVLM against Claude Vision for alt-text. Amended by [ADR 0011](0011-close-alt-text-engine-comparison.md): that first use was cancelled; the table isn't built.
7. [Java version: 21, not 25](0007-java-version.md) — use Java 21 (not the newer Java 25) for veraPDF and OpenDataLoader, since Java 25 has a live, unresolved JDK regression affecting the `ServiceLoader`/JPMS mechanism both tools' Apache PDFBox-based Java engines rely on.
8. [Storage layout keyed by document, not filename](0008-storage-layout.md) — key storage paths by `(service_account, content_hash)` rather than upload filename, so every attempt on a document groups together and multi-tenant isolation is preserved on disk, not just in the DB.
9. [No retry mechanism yet; resubmitting a failed document no longer auto-retries](0009-no-retry-mechanism-yet.md) — dedup and retry are different concerns; a `FAILED` document now stays reported as `FAILED` on resubmit instead of silently kicking off a new job. Retry mechanism is deferred for the future. Superseded by [ADR 0014](0014-versioned-retry.md).
10. [Fix OpenDataLoader's hybrid+tagged-pdf bug upstream](0010-fix-opendataloader-hybrid-tagging-upstream.md) — OpenDataLoader's hybrid mode silently drops OCR-recovered text from `tagged-pdf`/`pdf` output (confirmed bug); rather than working around it downstream, fork `opendataloader-pdf`, fix the bug directly, pin our Docker build to the patched fork, and contribute the fix upstream. Keeps the `ocr` step a single call (no separate `build_tags` step) and preserves the original document's exact visual appearance. Also renames `finalize_tags`/`TaggingService` to `finalize_metadata`/`MetadataService`, since that step never touched tag structure, only document metadata.
11. [Close the alt-text engine comparison without running it](0011-close-alt-text-engine-comparison.md) — amends [ADR 0005](0005-alt-text-engine.md)/[ADR 0006](0006-engine-comparison-tracking.md): once `AltTextService` existed, decided not to run the SmolVLM-vs-Claude-Vision comparison or build `EngineComparisonSample` for it — a 256M-parameter model is very unlikely to meet the WCAG bar, a strong enough inference from model scale alone.
12. [Automatic semantic versioning via Conventional Commits](0012-automatic-semantic-versioning.md) — `python-semantic-release` tags a new `vX.Y.Z` release on every push to `main` based on Conventional Commit messages; the git tag itself (not a file in the repo) is the running app's `PIPELINE_VERSION`, stamped onto every `Remediation` row.
13. [Pipeline continues past a failed step](0013-pipeline-continues-past-a-failed-step.md) — amends [ADR 0003](0003-pipeline-steps-and-branching.md): every step now catches its own failures and lets the pipeline run to completion instead of aborting the whole job, since a partially-remediated document is more useful than none.
14. [Versioned retry for failed remediations](0014-versioned-retry.md) — supersedes [ADR 0009](0009-no-retry-mechanism-yet.md): resubmitting a `FAILED` document auto-retries if its `pipeline_version` is strictly older than an admin-set `PipelineConfig.retry_floor_version`; `force=true` always retries regardless of status. No bulk/proactive retry mechanism — raising the floor only affects future resubmissions.
15. [`final_output_uri`, a download endpoint, and multi-subscriber webhooks](0015-multi-subscriber-webhooks-and-download.md) — every `Remediation` records its terminal output (success or failure alike, per ADR 0013); `GET /api/document-download/<content_hash>/` serves it; any number of callers can each register their own `callback_url` per submission attempt (not one per document), notified via a signed `send_webhook_notification` task keyed by the callback, not the remediation.
16. [django-knox replaces DRF token auth](0016-knox-multi-token-auth.md) — swap DRF's single, plaintext, never-expiring `Token` for django-knox: a `ServiceAccount` can hold multiple hashed tokens with a sliding 1-year expiry, minted via `ServiceAccountService.issue_token()` (shell/admin only, no public API), with a clean-break cutover.
