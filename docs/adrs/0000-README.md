# Architecture Decision Records

1. [Web framework: FastAPI (v1) vs. Django for the rebuild](0001-fastapi-vs-django.md) — rebuild on Django + DRF instead of keeping v1's FastAPI app, since Django's built-in auth, ORM, admin, and storage give durable multi-tenant job state essentially for free. Amended by [ADR 0016](0016-knox-multi-token-auth.md): its DRF `TokenAuthentication` was replaced by django-knox.
2. [Task execution framework for the remediation pipeline](0002-task-execution-framework.md) — use Django's first-party `django.tasks` (`ImmediateBackend` locally, swappable to Cloud Tasks later via config) to run remediation out-of-band, avoiding Celery/RQ's always-on broker and worker requirement.
3. [Remediation pipeline: artifact-based step architecture](0003-pipeline-steps-and-branching.md) — the pipeline is a fixed sequence of six responsibility-based stages, each recording its outcome as an immutable `RemediationArtifact` row. One renamed step (`finalize_tags` → `finalize_metadata`) — see [ADR 0010](0010-fix-opendataloader-hybrid-tagging-upstream.md). Amended by [ADR 0013](0013-pipeline-continues-past-a-failed-step.md): a failed step no longer fails the whole job — the pipeline now runs to completion regardless, since a partially-remediated document is more useful than none.
4. [OCR/tagging engine: OpenDataLoader as a pinned dependency](0004-ocr-tagging-engine.md) — pin Java + OpenDataLoader (hybrid Docling mode) as a real, named dependency for the `ocr`/`finalize_metadata` stage rather than hiding it behind a generic swappable OCR interface, since OpenDataLoader can't cleanly separate OCR from tagging anyway. Amended by [ADR 0010](0010-fix-opendataloader-hybrid-tagging-upstream.md): OpenDataLoader's hybrid+tagged-pdf combination was found broken, then fixed directly via a fork contributed upstream, rather than worked around downstream.
5. [Alt-text engine: Claude Vision](0005-alt-text-engine.md) — use Claude Vision for the `alt_text` stage for now, since v1 already validated it end-to-end, while flagging OpenDataLoader's built-in SmolVLM output as untested against the WCAG bar and worth a real future comparison. Amended by [ADR 0011](0011-close-alt-text-engine-comparison.md): that comparison was decided against, not run.
6. [General mechanism for tracking engine/service comparisons](0006-engine-comparison-tracking.md) — add a permanent, reusable `EngineComparisonSample` table (gated by `RUN_ENGINE_COMPARISON_LOGGING`) for logging and manually comparing any two services' output on the same input, first used to compare SmolVLM against Claude Vision for alt-text. Amended by [ADR 0011](0011-close-alt-text-engine-comparison.md): that first use was cancelled; the table isn't built.
7. [Java version: 21, not 25](0007-java-version.md) — use Java 21 (not the newer Java 25) for veraPDF and OpenDataLoader, since Java 25 has a live, unresolved JDK regression affecting the `ServiceLoader`/JPMS mechanism both tools' Apache PDFBox-based Java engines rely on.
8. [Storage layout keyed by document, not filename](0008-storage-layout.md) — key storage paths by `(service_account, content_hash)` rather than upload filename, so every attempt on a document groups together and multi-tenant isolation is preserved on disk, not just in the DB.
9. [No retry mechanism yet; resubmitting a failed document no longer auto-retries](0009-no-retry-mechanism-yet.md) — dedup and retry are different concerns; a `FAILED` document now stays reported as `FAILED` on resubmit instead of silently kicking off a new job. Retry mechanism is deferred for the future. Superseded by [ADR 0014](0014-versioned-retry.md).
10. [Fix OpenDataLoader's hybrid+tagged-pdf bug upstream](0010-fix-opendataloader-hybrid-tagging-upstream.md) — OpenDataLoader's hybrid mode silently drops OCR-recovered text from `tagged-pdf`/`pdf` output (confirmed bug); rather than working around it downstream, fork `opendataloader-pdf`, fix the bug directly, pin our Docker build to the patched fork, and contribute the fix upstream. Keeps the `ocr` step a single call (no separate `build_tags` step) and preserves the original document's exact visual appearance. Also renames `finalize_tags`/`TaggingService` to `finalize_metadata`/`MetadataService`, since that step never touched tag structure, only document metadata.
11. [Close the alt-text engine comparison without running it](0011-close-alt-text-engine-comparison.md) — amends [ADR 0005](0005-alt-text-engine.md)/[ADR 0006](0006-engine-comparison-tracking.md): once `AltTextService` existed, decided not to run the SmolVLM-vs-Claude-Vision comparison or build `EngineComparisonSample` for it — a 256M-parameter model is very unlikely to meet the WCAG bar, a strong enough inference from model scale alone.
12. [Automatic semantic versioning via Conventional Commits](0012-automatic-semantic-versioning.md) — `python-semantic-release` tags a new `vX.Y.Z` release on every push to `main` based on Conventional Commit messages; the git tag itself (not a file in the repo) is the running app's `PIPELINE_VERSION`, stamped onto every `Remediation` row.
13. [Pipeline continues past a failed step](0013-pipeline-continues-past-a-failed-step.md) — amends [ADR 0003](0003-pipeline-steps-and-branching.md): every step now catches its own failures and lets the pipeline run to completion instead of aborting the whole job, since a partially-remediated document is more useful than none. Amended by [ADR 0024](0024-split-failed-status.md): postcheck-still-noncompliant and genuine errors are now separate statuses.
14. [Versioned retry for failed remediations](0014-versioned-retry.md) — supersedes [ADR 0009](0009-no-retry-mechanism-yet.md): resubmitting a `FAILED` document auto-retries if its `pipeline_version` is strictly older than an admin-set `PipelineConfig.retry_floor_version`; `force=true` always retries regardless of status. No bulk/proactive retry mechanism — raising the floor only affects future resubmissions. Amended by [ADR 0024](0024-split-failed-status.md): retry applies to `NONCOMPLIANT` and `ERROR`.
15. [`final_output_uri`, a download endpoint, and multi-subscriber webhooks](0015-multi-subscriber-webhooks-and-download.md) — every `Remediation` records its terminal output (success or failure alike, per ADR 0013); `GET /api/document-download/<content_hash>/` serves it; any number of callers can each register their own `callback_url` per submission attempt (not one per document), notified via a signed `send_webhook_notification` task keyed by the callback, not the remediation.
16. [django-knox replaces DRF token auth](0016-knox-multi-token-auth.md) — swap DRF's single, plaintext, never-expiring `Token` for django-knox: a `ServiceAccount` can hold multiple hashed tokens with a sliding 1-year expiry, minted via `ServiceAccountService.issue_token()` (shell/admin only, no public API), with a clean-break cutover.
17. [Sentry for error monitoring](0017-sentry-error-monitoring.md) — use Sentry to catch unhandled exceptions from every request, plus every pipeline step's own swallowed-and-continued failure, for visibility before further deploy-prep changes (storage, workers) introduce new failure modes.
18. [S3-compatible storage backend, against a GCS bucket](0018-s3-compatible-storage-backend.md) — use django-storages' S3 backend against S3-compatible endpoint (HMAC key auth), so storage auth stays portable across hosts; every pipeline step reworked to go through local temporary copies instead of `default_storage.path()`, which neither `S3Storage` nor `GoogleCloudStorage` implement.
19. [Idempotent pipeline steps](0019-idempotent-pipeline-steps.md) — closes [ADR 0003](0003-pipeline-steps-and-branching.md)'s open consideration: steps skip work they already completed (verification steps replay their stored verdict), artifact rows are upserted, and already-finished remediations aren't re-run, so a repeated task can't duplicate work, crash on per-step uniqueness, or re-send webhooks.
20. [Database-backed task worker](0020-database-backed-task-worker.md) — amends [ADR 0002](0002-task-execution-framework.md): use `django-tasks-db` (tasks stored in Postgres, run by an always-on `db_worker` process) instead of Cloud Tasks, trading scale-to-zero for a portable, provider-neutral queue that also makes webhook retry backoff actually wait.
21. [Deployable image](0021-deployable-image.md) — one image for staging and production (only env vars differ): gunicorn by default, bound to Cloud Run's `$PORT`; WhiteNoise serves static files from inside the app, so no separate static host or bucket; docker-compose overrides the command to `runserver` for local dev.
22. [Automated staging deploys](0022-automated-staging-deploys.md) — PRs need passing `test` and `lint` (pre-commit hooks) checks to merge; release tags trigger Cloud Build to build the image, run migrations as a one-off job (stopping on failure), then update the app and worker job — updating images only, so settings and the schedule are kept. OCR image built on demand; production later adds a manual approval step.
23. [Scheduled batch worker](0023-scheduled-batch-worker.md) — amends [ADR 0020](0020-database-backed-task-worker.md): in deployed environments the worker is a Cloud Run job started every 15 minutes, which exits at once if nothing is queued and otherwise waits for OCR, runs `db_worker --batch`, and exits — cutting the idle worker cost from ~$260/month to a few dollars, at the cost of up to ~15 minutes' pickup delay. Local dev keeps the always-on worker. Amended by [ADR 0028](0028-staging-database-on-neon.md): every 20 minutes.
24. [Split `FAILED` into verdict statuses](0024-split-failed-status.md) — amends [ADR 0013](0013-pipeline-continues-past-a-failed-step.md)/[ADR 0014](0014-versioned-retry.md): job status becomes `COMPLIANT`/`NONCOMPLIANT`/`ERROR`/`SKIPPED` (plus `QUEUED`/`RUNNING`), so a still-noncompliant document is distinguishable from a crash, and a run with postcheck disabled isn't claimed compliant.
25. [Admins create organizations and service accounts](0025-admin-creates-organizations-and-accounts.md) — amends [ADR 0016](0016-knox-multi-token-auth.md): the admin can add an Organization (with a hand-named first service account) and re-enables service account `Add`, always via `ServiceAccountService.create()`, so onboarding a customer needs no shell; organization names become unique.
26. [Add organizations and service accounts separately](0026-add-organizations-and-service-accounts-separately.md) — amends [ADR 0025](0025-admin-creates-organizations-and-accounts.md): organizations and service accounts are added in two steps with Django's default forms; usernames are generated, and a service account's name need only be unique within its organization (a database constraint), so no custom name checks are needed.
27. [Named tokens and token management in the admin](0027-token-and-webhook-secret-admin-actions.md) — amends [ADR 0016](0016-knox-multi-token-auth.md): each token gets a name (new `ServiceAccountToken` model), tokens are created and revoked only through `ServiceAccountService`, knox's own Auth Tokens admin is removed, and the admin gains a token list/revoke page and a "Regenerate webhook secret" action.
28. [Staging database on Neon, worker every 20 minutes](0028-staging-database-on-neon.md) — amends [ADR 0023](0023-scheduled-batch-worker.md): staging's database moves from Cloud SQL (~$40/month) to Neon's free plan (0.25 CU, direct connection, scales to zero), and the worker runs every 20 minutes instead of 15 to stay within the free compute hours; pausing the scheduler is now all it takes to shut staging off. Amended by [ADR 0029](0029-staging-worker-paused-by-default.md): the schedule stays paused on staging.
29. [Staging worker paused by default](0029-staging-worker-paused-by-default.md) — amends [ADR 0028](0028-staging-database-on-neon.md): the staging worker's scheduler trigger stays paused and the worker is run by hand, to save Neon's free compute-hours; the worker shares the app's `dice-database-url` (no Cloud SQL proxy), Neon's free plan has only a 6-hour restore window, and ADR 0028's rollback steps are corrected.
30. [Per-account limits](0030-per-account-limits.md) — each service account stores a `max_in_flight` cap and a submission limit per second, minute, hour or day (e.g. 100 per day), editable in the admin on Add and Edit; an "unlimited" checkbox skips both (blank values never mean unlimited), and enforcement is separate work.
31. [API throttling](0031-api-throttling.md) — enforces each account's submission limit (`429` with `Retry-After`; repeats are free), limits wrong tokens and a loose per-IP backstop by real caller IP, allows one unfinished attempt per document, and reports limits in `X-RateLimit-*` headers.
32. [Browser security settings](0032-browser-security-settings.md) — amends [ADR 0021](0021-deployable-image.md): https redirect, HSTS (starting at one hour), nosniff and a same-origin referrer policy are on whenever `REQUIRE_HTTPS` is on (the default; local dev turns it off); subdomain/preload HSTS stay off on purpose; CI runs `check --deploy` and fails on any warning.
33. [No proxy-hops startup warning](0033-no-proxy-hops-startup-warning.md) — amends [ADR 0031](0031-api-throttling.md): removes the startup warning about `TRUSTED_PROXY_HOPS` being 0, since it needed a `DEBUG` check to know if the app was deployed; the value is set explicitly in Terraform and the staging guide instead, and defaults to 0.
34. [Cloudflare ranges live in code](0034-cloudflare-ranges-in-code.md) — amends [ADR 0031](0031-api-throttling.md): `CLOUDFLARE_IP_RANGES` is a reviewed list in `settings.py`, no longer an environment variable, since the ranges change about yearly and an env change is a new deployment anyway.
35. [Startup config warnings](0035-startup-config-warnings.md) — on startup, reports a Sentry warning (never refuses to start) if `S3_BUCKET_NAME` is unset, `RUN_ALT_TEXT` is on without `ANTHROPIC_API_KEY`, or `RUN_OCR` is on without `OPENDATALOADER_HYBRID_URL`; the OCR URL no longer defaults to localhost.
36. [Origin lock](0036-origin-lock.md) — amends [ADR 0021](0021-deployable-image.md): if `ORIGIN_LOCK_SECRET` is set, middleware returns 403 to any request missing the `X-Origin-Secret` header Cloudflare adds, so the raw `run.app` URL can't bypass Cloudflare; empty (default) turns it off. Rejections are logged, and a startup warning fires if `REQUIRE_HTTPS` is on without a secret.
37. [Health check endpoint](0037-health-check-endpoint.md) — amends [ADR 0036](0036-origin-lock.md): `GET /ping/` is a normal view returning `pong!`, exempt from the origin lock (`GET`/`HEAD` only) so Cloud Run probes work, but under the usual per-IP throttle, with Cloud Run's max instances as the deployment-level cap; it uses the database (so wakes Neon), and probes must send an allowed `Host`.
38. [Worker-only OCR URL warning](0038-worker-only-ocr-url-warning.md) — amends [ADR 0035](0035-startup-config-warnings.md): the "`RUN_OCR` on without `OPENDATALOADER_HYBRID_URL`" warning is sent by the `run_queued_tasks` worker (when work is queued) instead of every process at startup, since the web app never calls OCR.
39. [Nightly database backup](0039-nightly-database-backup.md) — follows [ADR 0029](0029-staging-worker-paused-by-default.md): `manage.py backup_database` wraps `django-dbbackup` (`pg_dump` in the app image), run nightly as a Cloud Run job with its own service account, uploading to a separate R2 bucket and keeping the newest 14; failures go to Sentry.
40. [One OpenTofu module for staging and prod](0040-shared-opentofu-module-for-staging-and-prod.md) — amends [ADR 0022](0022-automated-staging-deploys.md): staging and prod are built from one module (`deploy/terraform/modules/dice`), each with its own settings and its own state in its own R2 bucket; differences (backup, origin lock, paused schedule, sizes, no custom domain on staging) are module inputs, and prod was moved into the module with no plan change.
41. [A Cloudflare Worker reaches Cloud Run](0041-cloudflare-worker-reaches-cloud-run.md) — amends [ADR 0036](0036-origin-lock.md): a Worker (in OpenTofu, Free plan) forwards the public hostname to the `run.app` address, adding `X-Origin-Secret` and `X-Forwarded-Host`, because Cloud Run routes by `Host` and a Transform Rule can't change it; Django reads `X-Forwarded-Host` when `USE_X_FORWARDED_HOST` is on (prod only, safe only with the lock on).
